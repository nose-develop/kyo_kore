# 実装設計

## 前提

実装前に、プロジェクトに含まれる `AGENTS.md` のNext.js注意事項に従い、必要に応じて `node_modules/next/dist/docs/` の該当ガイドを確認すること。

## ディレクトリ構成案

```text
/app
  page.tsx

/components
  ModeSelector.tsx
  TaskInput.tsx
  TaskList.tsx
  ResultCard.tsx
  WeightedTaskInput.tsx

/types
  task.ts

/utils
  random.ts
```

既存プロジェクト構成に合わせ、不要に細かく分割しすぎない。1日制作のMVPでは、最初は `app/page.tsx` に寄せて実装し、見通しが悪くなった時点でコンポーネント化してもよい。

## コンポーネント責務

### `ModeSelector`

- 3つのモードを表示する
- 現在選択中のモードを強調する
- モード変更イベントを親へ渡す

### `TaskInput`

- タスク名入力を扱う
- 通常モードの追加処理を呼び出す
- Enterキー追加に対応する

### `WeightedTaskInput`

- タスク名と重要度入力を扱う
- 重要度を1から10に制限する
- Enterキー追加に対応する

### `TaskList`

- 入力済みタスクを表示する
- 重要度がある場合は表示する
- 削除イベントを親へ渡す

### `ResultCard`

- モードごとの結果を表示する
- 励ましメッセージを表示する
- 再抽選、入力に戻る、このタスクをやるボタンを表示する

## ユーティリティ

### `utils/random.ts`

実装候補:

- `pickRandomTask(tasks: Task[]): Task`
- `shuffleTasks(tasks: Task[]): Task[]`
- `pickWeightedTask(tasks: Task[]): Task`
- `pickEncouragement(): string`

## 状態遷移

```text
初期表示
  -> モード選択
  -> タスク入力
  -> 実行
  -> バリデーションOK
  -> 抽選中演出
  -> 結果表示
  -> もう一度決める / タスクを入力し直す
```

バリデーションNGの場合は結果表示へ進まず、入力エリア付近にエラーメッセージを表示する。

## 実装順序

1. 型定義とモード定義を作る
2. トップ、モード選択、タスク入力、タスク一覧を作る
3. タスク追加、削除、Enter追加を実装する
4. 共通バリデーションを実装する
5. 今日これだけモードを実装する
6. 適当優先順位モードを実装する
7. 重要度バイアス抽選モードを実装する
8. 結果表示を整える
9. 抽選中演出と励ましメッセージを追加する
10. スマホ幅で見た目と操作性を確認する

## Tailwind CSS方針

- 背景は明るめにする
- 操作エリアはカード状にまとめる
- ボタンは押しやすい高さにする
- 結果タスクは大きく表示する
- スマホでは余白を十分に取り、横スクロールを発生させない

## テスト観点

### 入力

- 空欄タスクを追加できない
- Enterキーで追加できる
- タスク追加後に入力欄が空になる
- 削除ボタンで対象タスクだけ削除できる

### 実行

- タスク0件でエラーが表示される
- タスク1件でエラーが表示される
- タスク2件以上で結果が表示される
- 再抽選で結果が更新される

### 重要度

- 重要度未入力でエラーが表示される
- 重要度0や11でエラーが表示される
- 重要度1から10で実行できる
- 重要度が高いほど抽選重みが大きくなる

### 表示

- スマホ幅でボタンが押しやすい
- 結果タスクが見やすい
- 優先順位リストが番号付きで表示される
- エラーメッセージが入力エリア付近に表示される
